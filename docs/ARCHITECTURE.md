# Architecture

## Repository layout

```
.github/     CI, issue/PR templates, and the community health files
             (CONTRIBUTING, CODE_OF_CONDUCT, SECURITY — GitHub reads them here)
design-reference/  Provenance of the Claude Design import
docs/        Architecture, deployment, design parity, assets, the revamp plan
public/      Static assets, served as-is
scripts/     Node tooling — audits, image manifest, preview. All wired to npm scripts.
src/         Application code
tests/       unit/ (Vitest) and e2e/ (Playwright)
```

### Why the config files sit at the root

Every root config was tested by moving it into `config/` and observing what
actually happened. **Six of the eight fail silently** — the build or the check
still reports success while doing the wrong thing.

| File                   | What happens if moved                                                                                                   | Failure mode |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------- | ------------ |
| `next.config.ts`       | Build succeeds; log reads `Running next.config` instead of `next.config.ts`. `reactCompiler: true` is lost.             | **Silent**   |
| `postcss.config.mjs`   | Tailwind stops running. `bg-night`, `text-cream` and every `desk:` variant disappear, so all six pages render unstyled. | **Silent**   |
| `tsconfig.json`        | `tsc --noEmit` prints its help text and checks nothing. Typechecking passes vacuously.                                  | **Silent**   |
| `vitest.config.mts`    | Tests run with defaults: no jsdom, no setup file, no path aliases — and still report green.                             | **Silent**   |
| `knip.config.ts`       | knip runs with defaults and reports the config itself as an unused file.                                                | **Silent**   |
| `.prettierrc.json`     | `--find-config-path` fails; Prettier checks against its own defaults, not ours, and reports success.                    | **Silent**   |
| `eslint.config.mjs`    | Hard error — flat config resolves from cwd only.                                                                        | Loud         |
| `playwright.config.ts` | Hard error — falls through to `vitest.config.mts` and crashes.                                                          | Loud         |

`package.json`, `package-lock.json` and `.gitignore` are fixed by npm and git.
`next-env.d.ts` is generated by Next at the root.

`.prettierrc.json` and `knip.config.ts` _can_ live as keys inside `package.json`
(both verified working). They are kept as files anyway: `.prettierrc.json` belongs
beside `.prettierignore`, which has no `package.json` equivalent, and
`knip.config.ts` is typed as `KnipConfig` — a JSON key would lose that.

Moving a config also breaks editor integration, since IDE extensions discover
these by the same root-relative rules.

## Layers

```
src/app/          Routing only — page, layout, route, error, sitemap, robots.
src/components/
  primitives/     The reuse layer — button, round-button, eyebrow, plate,
                  mark, rule, field, number-mark, background-video
  layout/         announcement-bar, site-header, the five site-footer variants,
                  section, dark-band, message-page
  motion/         reveal, stagger, marquee, scroll-cue, ken-burns
  patterns/       Composed, page-agnostic blocks — hero-slideshow, card-rail,
                  video-band, story-split, film-grid, cta-band, newsletter…
  sections/       Page-specific composition (home/, scents/, booking.tsx)
  seo/            Structured data
src/features/
  booking/        The one feature with real logic: schema, Calendly, UI
src/content/      Every string, number, image path and link. zod-validated.
src/styles/       globals.css (the token layer) + brand-constants.ts (its JS mirror)
src/lib/          cn, wrap
src/hooks/        use-active-index
src/proxy.ts      Security headers (Next 16's rename of middleware)
```

**One file or one folder.** A component is a single file (`primitives/rule.tsx`).
It only earns a folder when it genuinely has more than one file — which today is
just `sections/home/` and `sections/scents/`. Aggregate barrels
(`primitives/index.ts`, `layout/index.ts`, `motion/index.ts`) exist because many
callers import from them; per-component barrels re-exporting a single symbol are
pure indirection and are not used.

Routing concerns stay in `app/`; everything visual lives in the component tree
where the Reuse Gate can find it. Next.js documents "store project files outside
`app`" as a first-class strategy — that is what this is.

## The three standing rules, and what enforces them

| Rule                                     | Enforced by                                                                    |
| ---------------------------------------- | ------------------------------------------------------------------------------ |
| No raw colour outside the token layer    | `scripts/audit-tokens.mjs` — fails the build                                   |
| No component copied instead of varianted | `scripts/audit-reuse.mjs` — flags any long class string appearing in two files |
| No stranded or missing asset             | `scripts/audit-assets.mjs` — fails in both directions                          |
| No dead code                             | `knip` — zero unused files, exports, or dependencies                           |

All four run in `npm run verify`. The reuse audit is not decoration: it caught
three copied blocks during the redesign, which became `VideoBand`, `StorySplit`
and an existing `Eyebrow` variant.

## Tokens

`src/styles/globals.css` is the single source. Everything lives in Tailwind v4's
`@theme`, which emits the custom property **and** generates the utility — so a
value is declared exactly once. Only things that must not produce a utility
(`--nav-h`) sit in `:root`.

Only what the artboards reference is declared. They use exactly 13 of the
`classical` system's tokens, so the ramp is trimmed to those and the brand layer
the artboards use raw is added on top — `night`, `cream`, three overlay veils,
two easing curves and the 79px nav height.

Three deliberate absences:

- **No alpha tokens.** Tailwind's `/N` modifier compiles `text-ink/66` to the
  same `color-mix(in srgb, …)` the artboards write inline, so the 27 ad-hoc
  alphas they spend need no tokens at all.
- **No spacing scale.** The artboards set spacing in raw pixels and reference
  `--space-*` nowhere, so Tailwind's default 4px scale applies — and it lands on
  the design's own rhythm exactly (`p-14` is 56px, `gap-18` is 72px).
- **One breakpoint.** All six artboards carry a single `max-width: 860px` query,
  so Tailwind's five defaults are cleared and `desk` (861px) is the only one.

### A trap worth knowing about

`src/lib/cn.ts` extends `tailwind-merge` with the project's font-size scale.
This is load-bearing. tailwind-merge's fallback for an unrecognised `text-<x>`
is _colour_, so without that list it reads `text-caption-sm` as a colour,
decides it conflicts with `text-cream`, and silently drops one of them. That
removed the label colour from every button variant and rendered the 190px step
watermark at the inherited 15px, with no error anywhere.
`tests/unit/cn.test.ts` fails if the list and `globals.css` drift apart.

## Booking

```
BookingForm ──> /api/availability ──> lib/calendly-api.ts ──> Calendly REST (token)
     │                                  └─ lib/calendly.ts   shapes, windows, pre-fill map
     └─ Reserve ──> lib/calendly-widget.ts ──> Calendly's booking window
                         └─ postMessage "calendly.event_scheduled" ──> Confirmation
```

Calendly is the scheduler and the record; this app is the form in front of it.

| File                     | Runs on | Does                                                                                      |
| ------------------------ | ------- | ----------------------------------------------------------------------------------------- |
| `schema.ts`              | both    | The form's rules and the `/api/availability` contract, in zod                             |
| `lib/calendly-api.ts`    | server  | The only code holding `CALENDLY_TOKEN`. `server-only`, so a client import fails the build |
| `lib/calendly.ts`        | server  | Pure: response shapes, the 31-day request windows, question names → `a1`…`a10`            |
| `lib/calendly-widget.ts` | client  | Loads Calendly's popup on demand, and trusts messages from `calendly.com` only            |
| `lib/schedule.ts`        | client  | Groups UTC times into the visitor's own days, builds the pre-fill                         |
| `lib/phone.ts`           | both    | Normalises a typed number to E.164                                                        |

Times travel as UTC instants and are only turned into days and clock times in
the browser, in the visitor's zone — the same zone Calendly's window shows. The
server never decides what day it is for anyone.

Calendly's API can book on paid plans only. On the free plan the guest confirms
in Calendly's window; see `docs/DEPLOYMENT.md` for the setup and the failure
modes.

## Motion

The redesign animates entirely in CSS — four keyframes and a set of opacity and
transform transitions — so there is no animation library. `Reveal` reimplements
the artboards' `hs-motion.js`, including its rule that elements already on
screen are never hidden. Three properties are load-bearing:

1. Markup renders **visible**; hiding happens in a layout effect. Without JS the
   page is fully readable and crawlers never see blank sections.
2. Hiding runs **before paint**, so nothing flashes in and back out.
3. A safety timer reveals anything the observer misses, so content can never end
   up permanently invisible.

Reduced motion is handled globally in `globals.css`, which zeroes animation
**delay** as well as duration — with `animation-fill-mode: both`, a non-zero
delay leaves an element at `opacity: 0` for the whole delay.

## Testing

| Layer | Tool                     | Covers                                                                                                                                           |
| ----- | ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| Unit  | Vitest                   | Calendly windows and pre-fill mapping, the availability route, form rules, content integrity, carousel index arithmetic, the `cn` merge contract |
| E2E   | Playwright × 4 viewports | every route renders, no overflow, links resolve, anchors land, booking flow, and a button-by-button sweep of every control the artboards draw    |
| A11y  | axe-core                 | WCAG 2.2 AA on all six routes, heading order                                                                                                     |

Playwright runs desktop (1440), laptop (1024), tablet (768) and mobile
(iPhone 13 / WebKit) — two of them above the design's 861px line and two below.
Accessibility runs are made under `prefers-reduced-motion` so axe measures
settled state rather than mid-transition opacity, and `/booking` is scanned only
once its calendar has loaded.

The booking suite runs against `tests/mocks/calendly-api.mjs`, a local stand-in
for the three Calendly endpoints the site reads. It enforces Calendly's own
limits — bearer token, start in the future, at most 31 days per request — so a
regression in how the site asks fails here rather than in production. Calendly's
popup script is stubbed per test to record exactly what it was asked to open.

375 e2e tests pass; the 9 skips are the design-intended ones — the
desktop-only rails below `desk`, the phone-only checks above it, and the skip
link on WebKit, which does not tab to links by default.
